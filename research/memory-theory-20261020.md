# Research: архитектуры памяти агентов — теория для поста (20.10.2026)

## Источники (проверены 20.10)

1. **«A Survey of Agent Memory in the Second Half»** — arXiv 2602.06052v4 (UIC/UIUC/Stanford/Salesforce и др., ~27 авторов): сотни работ по памяти агентов вышли в 2025. Таксономия: субстраты (internal / external / mixed), субъекты (user-centric / agent-centric). Тренд: память как субстрат самоэволюции — краткосрочная память гейтит выбор и абстракцию опыта в ходе выполнения, долгосрочная консолидирует его в переиспользуемые знания и скиллы. Центральная проблема «второй половины»: context explosion в long-horizon задачах.
2. **MemGPT (arXiv 2310.08560, Letta)** — иерархия памяти «как в ОС»: core memory в контексте vs внешние слои (conversational / archival / files), агент сам управляет, что держать в контексте. Прародитель всех слоёных дизайнов, включая наш Layer 0.
3. **Letta Filesystem benchmark (letta.com/blog/benchmarking-ai-agent-memory)** — LoCoMo: простой файловый агент (gpt-4o-mini, grep/search/open) = **74.0%**, против заявленных Mem0 **68.5%** (graph-вариант). Вывод Letta: **возможности агента важнее механизма памяти** — итеративный поиск по файлам бьёт специализированные memory-тools; простые инструменты чаще в обучающих данных и потому используются эффективнее. (Флаг: Mem0 не согласился с методологией — спор публичный, issue mem0#3004.)
4. **«How Memory Management Impacts LLM Agents» (ACL 2026, Harvard/MSU)** — эмпирика: свойство **experience-following** (похожий вход → похожий выход из retrieved-памяти) даёт два режима отказа: **error propagation** (ошибка в памяти тиражируется и усиливается в будущих задачах) и **misaligned experience replay** (внешне корректные записи дают misleading value). Вывод: качеством памяти-банка надо управлять явно; оценки будущих задач = бесплатные метки качества для записей. → прямое теоретическое подтверждение нашего правила протухания/реестра решений.
5. **Mem0 (github mem0ai/mem0)** — «memory layer for AI agents», новый алгоритм (апрель 2026), заявляет рост LoCoMo 71.4→**96.5%** и снижение токенов/латентности (self-reported).

## Карта эволюции (для теории поста)

- **Gen 1:** всё в контекст → окно кончается.
- **Gen 2:** внешняя память + retrieve (вектора/графы): Mem0, Zep, LangMem — retrieval-бенчмарки, споры о методологии.
- **Gen 3 (сейчас):** слоёная память с маршрутизацией записи — горячий слой (core) + процедуры + канон + явные правила what-goes-where; агент сам управляет иерархией (MemGPT-наследие).
- **Фронтир (из survey/ACL):** управляемое протухание и качество записей (error propagation — измеримый вред), память как субстрат self-evolution, RL-политики памяти (Memory-R1 и др.).
