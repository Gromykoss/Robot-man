## Что это (проверено первоисточниками)

LLM-native браузерная автоматизация: один статический Rust-бинарник (3.8 MB измерено), говорит CDP с Chrome напрямую. Без MCP, без Node-runtime, без облака. Ставится агенту: `npx skills add sderosiaux/chrome-agent` → SKILL.md (формат Hermes-совместимый).

## Ключевая идея (их формулировка)

«Other browser tools tell your AI agent the click worked. chrome-agent reads the page back after every action and answers in JSON what actually happened.»
Каждое мутирующее действие возвращает `verdict` + `verdict_reason` + `next` (закрытый словарь из 6 значений: proceed/inspect/retry/confirm/dismiss/stop). `ok:true` = команда исполнилась, НЕ что страница подчинилась — агент обязан читать verdict до декларации успеха.

## Цифры автора (Medium-пост)

- Playwright MCP: ~114,000 токенов на браузерную задачу; chrome-agent inspect: ~50 токенов (заголовок поста)
- 15-30k токенов HTML страницы → ~500 токенов текста (Mozilla Readability)
- Честная поправка автора: «10x faster» на деле 1.5x на чтениях, 1.1x на действиях, ~12ms/команда
- Stealth: 6 CDP-патчей против Cloudflare/Turnstile; DataDome/Kasada — только --connect к реальному Chrome (фингерпринт бинарника не обмануть)

## Dogfood-тест на нашем сервере (16.09, сделано)

Установка: `npm install chrome-agent@0.16.0` — 0 зависимостей, npm-пакет 20kB + предсобранный линуксовый бинарник 3.8MB (статический ELF). Пакет верифицирован (maintainer chtefi = автор, first publish по npm).

Нюансы запуска на headless-сервере (не нашёл Chrome в PATH — ожидаемо):
1. Инструмент ищет google-chrome/chromium по имени; `--browser` — это имя профиля, не путь (спорный UX)
2. Chrome 136+ блокирует remote debugging на дефолтном профиле — hint сам подсказал решение (запустить с отдельным --user-data-dir), это их fail-verbose дизайн в действии
3. Подключился через `--connect http://127.0.0.1:9222` к Chromium for Testing 150 (playwright cache) — всё заработало

**Живые замеры (HN front page):**
- goto + inspect full tree: 22,363 символов ≈ 5,590 токенов
- inspect --filter "link,button": 6,852 симв ≈ 1,713 токенов
- extract (все 30 заголовков HN): 6,672 симв ≈ 1,668 токенов — структурированные Title|URL|Fields одной командой, селекторов не надо
- read (статья): 13,260 симв ≈ 3,315 токенов чистого текста
- goto+extract на 5 items: 0.57 сек суммарно
- assert text --contains "System One" → exit 0 «held» — exit-code как доказательство (0 = held, 2 = не выполнилось, 1 = не проверено)
- Ошибка: click n9999 → JSON с полным hint почему и что делать (uid устарел после goto) — fail-verbose работает

**Вердикт dogfood:** работает как заявлено. Verify-after-every-action реально отличает «клик отправлен» от «клик сработал». На нашем сервере встал без сборки (готовый бинарник), единственный барьер — именованный поиск Chrome (решился symlink'ом).

## Mission docs (прочитаны, mission.md решение 13.09)

«Make websites learnable by agents» — превратить сайты в capabilities, которые агенты сами дисковерят, верифицируют, переиспользуют и чинят. Discovery driven by the calling agent (reasoning — наш, execution protocol — их). Recipes = пакеты переиспользуемых capability с условиями применения, проверками, evidence. Изменение сайта → точечное переоткрытие маршрута, не всё заново. Каталог рецептов на GitHub с независимой валидацией — planned, не сделано (честно: discovery-протокол реализован частично, catalogue/acceptance — в роадмапе).

## Тройственная картина (тест Сергей+Junior 15-16.09, живой материал)

1. **Баррикады** — WB (498), Ozon (403 AntibotDTO), Ламода (слайдер-капча): блок по IP до контента, --stealth не помогает. Экономическая логика: трафик без человека = убыток.
2. **Дружелюбные** — HN, docs-сайты: чистый HTML; прослойка стандартов (MCP-серверы, WebMCP document.modelContext — chrome-agent умеет webmcp list/call, llms.txt). Мотивация: агент = новый канал трафика.
3. **Промежуточный (мосты)** — chrome-agent отсюда: не ломает баррикады, а делает доступное накопляемым (discovery → recipes → repair). DDG-нюанс: капча «выбери уток» на обычном поиске — дружелюбность кончается на пороге, где поведение непохоже на человеческое.
Связь с ozon-mcp: веб-фронт Ozon = лагерь 1 (тупик), мобильный API-реверс = свой путь к лагерю 2; chrome-agent архитектурно совместим — мог бы взять ozon-mcp как готовую capability.
