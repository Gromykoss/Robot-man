## Русский драфт

Продолжаю серию про нашу шину агентов (self-hosted Nostr relay + Hermes gateway). Прошлые части: подъём релея, штаб из 5 агентов, SSH вместо GitHub-файлов, агенты, будящие друг друга. Сегодняшний слой: **профили не живут в шине постоянно — и это ок. Схема ниже доставляет каждому адресованное сообщение в его живую сессию.**

### Архитектура

```
agent-bus (Nostr)
   │  сообщение с @упоминанием профиля
   ▼
multiplex gateway (buzz-адаптеры всех профилей под их nsec)
   │  hook pre_gateway_dispatch: чат=agent-bus И адресован этому профилю?
   ▼ да → inject_gateway_message в Telegram-сессию профиля + skip (в шину не дублировать)
   │  нет → пропуск
   ▼
профиль отвечает в своей TG-сессии → ответ уходит в шину от его pubkey
```

### Предпосылки (что должно быть до)

1. Relay self-hosted, TLS через Caddy+LetsEncrypt (иначе WSS не поднимется)
2. У каждого профиля свой nsec в credentials, один скрипт отправки читает ключ по имени профиля (`--as <profile>`, дефолтного отправителя быть не должно — мисаттрибуция ловится только так)
3. `require_mention: true` в шине — профили отвечают только когда адресованы. Это главная защита от эхо-петли (мы проходили: 4 профиля писали «Тишина» десятками раз с интервалом 2–10 с)

### Слой 1: инъекция в живую сессию (плагин)

Плагин на хуке `pre_gateway_dispatch`:

```
событие: source.profile == <профиль> AND chat == agent-bus
         AND (display_name | alias | pubkey в адресатах)
→ inject_gateway_message(session_key="agent:<p>:telegram:group:<id>", content, plugin_id)
→ return {"action": "skip"}   # иначе сообщение дублируется в шину
```

Anti-echo: сообщения авторов-профилей не форвардятся никогда.

Три места, где это молча ломалось (у каждого — свой симптом):

- **Discovery:** профильный scope ищет плагины в `profiles/<p>/plugins`, а не в корневом `plugins/` → симлинк каждого профиля на общий каталог
- **Оптин-семантика:** профильный scope читает конфиг профиля, и если в нём нет `plugins.enabled` — юзер-плагины скипаются без ошибок в логе. Симптом: хук не вызывается, хотя плагин установлен
- **Инжектор:** gateway-инъекция живёт в root-менеджере → плагин резолвит его через `_plugin_managers_by_home`

### Слой 2: детерминированный session_key

Инъекция пишет в `agent:<p>:telegram:group:<id>`. Если ключ недетерминирован (дрейф активного профиля, нестабильный суффикс участника), сообщение уходит в «никуда» — одну из 10 вариантов сессий. Фикс: `build_session_key` без participant-суффикса для групп, профиль резолвится от канала, не от активного процесса. Проверка — запросом в state.db:

```
SELECT DISTINCT session_key FROM sessions WHERE source='telegram';
```

Должен быть ровно один ключ на канал. У нас до фикса было 15, включая три варианта для одного чата.

### Слой 3: убрать второй канал доставки

Пока не пометить профили `external: true` в конфиге старого роутера, каждый адресованный профиль получает ДВА запуска: один через gateway-инъекцию, один — роутер спавнит сессию профиля. Симптом: два ответа на одно сообщение. Юнит-тесты функций не ловили — поле конфига молча терялось при сборке dataclass. Проверять сквозняком: config → dataclass → filter → delivery.

### Проверка (не самоотчёт)

Тест 1: @RAB9 в agent-bus → ответ RAB9 из шины (VERIFIED, turn 15.9s).
Тест 2: адресованное RAB9 сообщение → появилось в TG-группе rab9 как входящее → ответ там же → подтверждение в шине.
Тест 3: НЕ адресованное сообщение → ноль реакций, ноль логов.

### Что это открывает

Профиль не должен «жить» в шине, чтобы её слышать. Каждый отдел остаётся в своей рабочей сессии с полным контекстом задачи, а шина доставляет адресованное как входящее. На этой схеме у нас заработали кросс-отделные запросы (профиль → оператор → чужой профиль) и будильник Desktop-агента (зеркальный poller `dispatch("prompt.submit")`, транспорт в живой UI-websocket — там другой рантайм, `inject_message` через CLI-ref не работает).

## Заметки для Сергея

1. Формат — пост-инструкция по канону 19.08 («Cities»): как повторить, не сказка. Урок того поста соблюдён: техническая ценность целиком, не конденсирую в варстори.
2. Все факты из map/buzz.md (План А/Б VERIFIED 31.08) + хронологии директора (18.08 native inject, 22.08 external-заглушки, 24.08 session_key, 19.08 Junior-poller). Приукрашиваний нет — «три недели» и прочие обобщения убраны.
3. Порядок слоёв осознанный: инъекция → session_key → external-заглушка. Именно в таком порядке мы это чинили; читатель, повторяющий у себя, спотыкается о те же грабли в том же порядке.
4. Код-фрагменты — псевдо, не вырезки из боевого кода (названия функций и семантика настоящие: `inject_gateway_message`, `pre_gateway_dispatch`, `prompt.submit`). Если хочешь — вставлю реальные 3-5 строк из плагина вместо псевдо.
5. EN-финал будет ~3200-3400 знаков (русский сжимается при переводе) — в лимит 4000 помещается.
6. Обложка: скелет поста — шина → развилка → живая сессия. Без роботов-за-мониторами, без буквального «будильника».
