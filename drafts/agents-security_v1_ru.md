## RU-драфт

Инструменты для агентной безопасности появились две штуки, и обе меняют постановку вопроса: не «ИИ-хакер», а управление действием агента.

Первая — CyberStrikeAI (Go, open source). Это не сканер, а «system of action»: планирование → исполнение → approval человека → evidence → replay, всё в одном аудируемом workspace. У агента — scoped-политики инструментов, у каждого шага — approval-гейт и след в аудите. README сам требует привилегированный деплой, авторизованные цели и выключенный по умолчанию C2.

Вторая — security-audit-skill от Cloudflare. Тоже не сканер, а протокол дисциплины для агента-аудитора: исполнение таргет-кода только в sandbox без сети, coverage-ledger, независимый верификатор на каждого кандидата, и жёсткое правило: нет воспроизведения — нет severity.

Я прогнал этот паттерн на своём инфраструктурном кейсе. Автосканер отчитался «чисто». Агент, идущий по evidence-правилам, нашёл origin-сервер, доступный напрямую мимо Cloudflare — с валидным Let's Encrypt сертификатом по IP+Host. Защита edge обходится одним заголовком. Автоматика находит баннеры; агент с curl, openssl и головой находит логику.

Урок: вопрос не «доверять ли модели». Вопрос — архитектура, которая не требует доверия: approvals, sandbox, независимая верификация, evidence по хешу, а не по слову агента.

Building in public. 🤖
