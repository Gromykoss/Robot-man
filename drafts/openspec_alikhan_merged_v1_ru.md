## Что OpenSpec есть на самом деле

Слой соглашения между человеком и coding-агентом:

1. Markdown-артефакты в репозитории  
2. CLI (`openspec …`) — init, status, config, merge  
3. Slash-команды в чате ассистента (`/opsx:propose`, apply, verify, archive)

Это не компилятор, не рантайм, не замена тестов и code review. Код по-прежнему пишет модель. Меняется **вход**: вместо плавающего чата — папка с намерением, дельтой поведения, дизайном и чеклистом.

Две оси:

- `openspec/specs/` — **как система ведёт себя сейчас** (capability + SHALL + Given/When/Then). Без имён классов и выбора библиотек.  
- `openspec/changes/<name>/` — одно изменение: `proposal.md`, delta specs, `design.md`, `tasks.md`, потом archive в библиотеку.

Дельта — нетривиальная часть:

| Секция | Archive |
|--------|---------|
| ADDED | дописывает |
| MODIFIED | **целиком заменяет** требование (не патч-строка) |
| REMOVED | удаляет; retire capability — отдельный флаг |

Неполная MODIFIED = тихая порча библиотеки истины. Два активных change на одно requirement при последовательном archive затирают друг друга. Автослияния сценариев нет.

Цикл, который стоит денег:

```
propose → ревью плана → apply → verify/ревью кода → archive
         дешёвая ошибка              дорогая ошибка
```

`/opsx:verify` — ещё один проход модели, не доказательство. Полезно как список дыр. Бесполезно как замена теста.

Archive без reconciliation записывает ложь в `specs/`. Дальше каждый агент добросовестно её воспроизводит.

## Что ролик продаёт лишнего

- «Непредсказуемая сеть → дисциплинированный исполнитель» — **не закон**. Направление полезное; модель всё равно прыгает через tasks, если человек не смотрит diff.  
- Центр = `project.md` + `idea.md` — **устаревшая/упрощённая** схема. После v1.0 ядро: `specs/` + change. `idea.md` в каноне нет.  
- «5 минут на внедрение» — init минуты; навык узких требований и честного archive — недели.  
- «Спека станет единственным рукописным артефактом» — гипотеза, не свойство инструмента. Спеки тоже пишет модель — их тоже надо читать.

Сильная часть ролика: brownfield, дельта вместо простыни, ревью плана **до** кода. Это совпадает с доками.

## Наш case за день (не «поставим CLI и хаос кончился»)

Исход: 148 `.md` без маршрута. Агент при баге шёл в код. Документация не была входом сессии.

Собрали **контракт-индекс** в том же духе (библиотека поведения + маршруты), без религии «установил OpenSpec = контроль»:

**Layer 1.** `PROJECT_MEMORY_GRAPH.md` — 47 строк, обязательный boot каждой сессии.  
**Layer 2.** 9 доменных карточек в `openspec/specs/` (роль, owners, traps, GIVEN/WHEN/THEN).  
**Layer 3.** MASTER_SPEC / DATA_CONTRACT / код — только по маршруту карточки.

В AGENTS.md — Contract Index Gate: deep docs через карточку; после смены домена — обновить граф/карточку или явно `Contract index update: not needed`.

~45 файлов ушли в архив. В корне — короткий набор из **16** entry-.md.

**Фантом:** `ojr_sync.py` описан в INDEX/MASTER_SPEC/RUNBOOK. В git add-коммитов = 0. Роль давно в `db.py` + `whatsapp_commands.py`. Свалка md держала имя файла, которого не было.

**Петля post-commit:** hook писал CHRONOLOGY на каждый коммит, включая `chrono:…` о самих записях (`6281db7 → 2cbe1d3 → 6685fc9 → 3a4d262`). Guard: `chrono:*` → exit 0.

**Пилот карточки vor-import** — не на бумаге. Реальный прогон: 573 кода · 0 insert · 573 update · 0 conflict · 573 unique · 554 с ценой. Baseline в карточке.

Graph view: 127 заметок с вики-связями + canvas 126 узлов / 141 ребро.

Сверка: Grok adversarial 4/4 · 36/36 путей графа на диске · review scope 45 passed (contracts, vor_reference, avr, qa_parser, smoke).

Честно: у нас **свой** contract-index в репо (граф + domain cards + gate). Это не отчёт «прогнали полный Fission CLI-конвейер end-to-end». Полезность = та же ось, что у OpenSpec: поведение отдельно от change, deep docs не на старте, дрейф ловится правилом, а не памятью чата.

## Когда окупается (и когда нет)

Окупается, если: изменение переживёт сессию/агента; цена «сделали не то» > двух страниц md; есть инварианты; кто-то читает proposal/дельту **до** apply.

Не окупается: опечатка на 15 минут; никто не ревьюит артефакты; спека пишется после кода «для archive»; набор скриптов без устойчивого поведения.

Минимальный контур без фреймворка:

1. Зафиксировать, что должно стать истинным и что ломать нельзя  
2. Разрезать на отмечаемые шаги  
3. После кода сверить с пунктом 1  
4. Сохранить рядом с кодом, не в чате  

OpenSpec автоматизирует этот контур и merge дельт. Магия = 0. Контроль = человек, который отклоняет плохой план и не архивирует расхождение.

## Урок

Свалка `.md` не делает агента осведомлённым — даёт ложные имена файлов и право чинить код в обход спеки.

Ролик OpenSpec правильно бьёт по vibe coding. Доки и практика говорят жёстче: без verify и без отказа archive библиотека истины гниёт быстрее чата.

Нам за день хватило 47-строчного входа, девяти карточек-маршрутов и gate. Фантомный модуль и chrono-петля всплыли только когда docs начали сверять с git, а не с «интуицией агента».
