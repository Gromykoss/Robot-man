BrowserSkill — bridge между AI-агентом и твоим настоящим, уже залогиненным Chrome. Открыл код Tencent: Rust-CLI `bsk` + локальный daemon + расширение Chrome/Edge, MIT. Не MCP — обычный CLI, работает с любым агентом, умеющим shell: Cursor, Claude Code, Codex, OpenClaw, Hermes Agent, DeepSeek Harness. 3.5k звёзд за три месяца.

Большинство browser-инструментов дают агенту пустой браузер. BrowserSkill даёт Agent Window внутри твоего Chrome, где сессии уже живые. Твои вкладки он не трогает — доступ только по явному запросу tab borrow, который ты подтверждаешь. Механика: агент зовёт bsk → daemon через локальный IPC → WebSocket на 127.0.0.1 → расширение выполняет. Страница возвращается как accessibility-дерево — текст, не скриншоты. Капча или логин — request-help: агент встаёт на паузу, шаг делает человек, потом агент продолжает.

Подтверждение borrow сделано без доверия к агенту. В 0.3.0 выпилили все bypass-флаги: --unattended, tab borrow --no-confirm и переменная BSK_REQUEST_HELP=off больше ничего не отключают. Единственный выключатель живёт в настройках расширения в браузере — из shell его не достать. Инсталлер проверяет sha256 архива перед распаковкой.

Та же философия в сообщениях об ошибках. Попытка дотянуться до чужой вкладки без borrow возвращает: operation denied by the Agent Window sandbox — hint: tabs outside an Agent Window must first be borrowed via `bsk tab borrow <tab-id> --session <id>`. Отказ человека: the user denied the tab borrow — hint: do not repeat the same authorization request. Ошибки не просто описывают сбой — они запрещают агенту его обходить.

Что проверено живьём на второй машине (Windows 11, Chrome 153): установка end-to-end ~30 минут, большая часть — ручные подтверждения Chrome: remote debugging включается только вручную, Google сознательно не даёт ставить это тихо. Agent Window открыл grok.com уже залогиненным — реальная история чатов в сайдбаре, ноль логинов и ноль клонов профиля. daemon продержался 6.5+ часов без рестарта; navigate/observe/snapshot — секунды.

Honest limits. Пермишены выдаются per-tool: второй агент в том же контуре запросил свой отдельный попап. CLI-синтаксис неровный: fill требует значение флагом --value, позиционный аргумент падает. При установке расширения daemon перезапустился сам. Поддержка — Chrome и Edge; Firefox только в планах, «other Chromium expected to work» без гарантии.

Контекст, почему этот класс инструментов появился именно сейчас: Cloudflare просканировал 200,000 самых посещаемых доменов — почти у всех есть robots.txt, написанный для поисковых краулеров, но только 3.9% сайтов отдают markdown агентам, а MCP Server Cards есть у нескольких десятков. Веб строился для людей и поисковиков; агенты — третья аудитория, к которой почти никто не готов. Пока стандарты (WebMCP, Agent Readiness) догоняют, bridge-инструменты заполняют разрыв с другой стороны: не сайт учится говорить с агентом, а агент подключается к браузеру, в котором человек уже всё сделал.

Две модели доступа агента к браузеру: клонировать профиль и надеяться, что сессия не протухнет, — или работать в настоящем браузере под явным контролем. BrowserSkill — вторая. Подтверждение, которое нельзя обойти флагом, — правильная конструкция: дело не в доверии к агенту, а в отсутствии у него переключателя.
