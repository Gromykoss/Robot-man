У агента было 148 markdown-файлов «документации». При баге он чинил код по интуиции. Спеки гнили и расходились с репозиторием.

Я собрал для него другую схему — не «ещё один README», а контракт-индекс с маршрутом чтения. Case: WhatsApp-бот стройки. Один рабочий день.

## Три слоя

**Layer 1 — вход сессии.**  
`PROJECT_MEMORY_GRAPH.md` — 47 строк. Обязательный старт каждой сессии. Purpose, boot rule, глобальные инварианты, карта доменов, change routing. Большие доки на старте не читаются.

**Layer 2 — 9 доменных карточек** (`openspec/specs/`).  
Каждая карточка: роль, канонические источники, code owners, соседние риски, traps, GIVEN/WHEN/THEN. Задача про домен → сначала карточка, потом только то, что она указала.

**Layer 3 — глубокие источники.**  
MASTER_SPEC, DATA_CONTRACT, код — только по маршруту из карточки. Не целиком «на всякий случай».

В AGENTS.md вшит Contract Index Gate: старт с графа; deep docs — через карточку; при изменении домена — обновить граф/карточку или явно записать `Contract index update: not needed`.

## Что выкинули

~45 файлов ушли в архив/удаление: мёртвые спецификации, разовые аудиты, старые briefings. В корне остался короткий набор из **16** entry-.md (фаза 1 сжала свалку; фаза 2 добавила `PROJECT_MEMORY_GRAPH.md` как вход T0).

## Что всплыло, когда начали сверять docs ↔ git

**Фантомный модуль.**  
`ojr_sync.py` описан в нескольких документах (в т.ч. INDEX / MASTER_SPEC / RUNBOOK). В git модуль **никогда не появлялся** (`git log --diff-filter=A` = 0). Реальная роль давно размазана между `db.py` и `whatsapp_commands.py`. Документация держала имя файла, которого не было.

**Петля в post-commit.**  
Hook писал строку в CHRONOLOGY на каждый коммит — включая коммиты «chrono: …», которые сами были записями о записях. Цепочка самозаписей: `6281db7 → 2cbe1d3 → 6685fc9 → 3a4d262`. Фикс — guard: `chrono:*` → exit 0. Живой тест пройден.
