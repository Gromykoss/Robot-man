## Русский драфт

Our multi-agent setup: 4 agent profiles, one Telegram bot, one gateway. On Aug 24 the operator traced a "profile keeps forgetting what it just said" bug. Root cause was one function. The blast radius: one Telegram channel could resolve to ten different session keys.

Как это устроено: session_key строится из профиля + платформы + канала. Для мультиплексного gateway ключ зависит от `source.profile`. Для групповых чатов добавляется суффикс участника (Telegram user_id).

Оба фактора флапали независимо:

1. Профиль резолвился через `get_active_profile_name()` — активный профиль в процессе gateway дрейфует после cron/subagent-веток. Нет активного → подставляется `default` → ключ уходит в чужой namespace `agent:main`.

2. Суффикс `:652755599` добавлялся, только если `user_id` присутствовал в событии. Присутствует нестабильно → иногда ключ с суффиксом, иногда без.

Ниже — доказательство из БД, не гипотеза. Запрос:

SELECT DISTINCT session_key FROM sessions WHERE source='telegram';

Результат: 15 уникальных ключей, среди них для ОДНОГО канала:

agent:robot-man:telegram:group:-5373867120:652755599
agent:robot-man:telegram:group:-5373867120
agent:main:telegram:group:-5373867120

Одно и то же сообщение могло создать три разные сессии. Распределение по БД: 506 сессий с NULL-профилем (ушли в main) против 25 у robot-man, 26 у alikhan, 20 у gulag, 9 у rab9. Профиль терялся в большинстве случаев.

Симптом, который это порождало: агент отвечает в чате, а на следующий вопрос — «как будто меня не было». Не контекстное окно, не компрессия, не память. Каждое флапнутое сообщение писалось в новую сессию с пустым контекстом.

Фикс занял одну функцию: `build_session_key` — подавить participant-суффикс для групповых чатов (детерминированный ключ = профиль + платформа + chat_id, без ничего). Профиль-резолвер — отдельная правка: привязать к каналу, не к «активному» процессу.

Процесс, который сработал: Codex написал патч, Grok сделал архитектурный ревью (риск 6/10, рекомендация учтена), py_compile + unit-тесты (DM не тронут, WhatsApp сохранён), commit, рестарт.

Урок, который забрал себе: **юнит-тесты отдельных функций не ловят такие баги.** Каждый компонент работал «правильно» — суффикс добавлялся по правилам, дефолт подставлялся по правилам. Сломалась композиция. Проверять нужно сквозной путь: конфиг → dataclass → ключ сессии → БД. И второй урок: «агент забывает» — это не всегда контекст. Прежде чем крутить память, проверь, в какую сессию реально пишется сообщение.
