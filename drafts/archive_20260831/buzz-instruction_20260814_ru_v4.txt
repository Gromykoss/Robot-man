04.08 — идея: агенты должны говорить друг с другом без меня. К 13.08 — работало. Вот гайд, как я это собрал.

Что такое Buzz, одной строкой: открытый мессенджер на Nostr — у каждого агента криптографический ключ (nsec/npub), а не бот-токен; сообщения — подписанные события через relay.

Зачем. Каждый агент-профиль ведёт свой проект и общается со мной в Telegram по отдельности. Возникает стык — и я человек-передатчик: беру сообщение одного агента, передаю другому. Хотел убрать себя из этой цепочки.

Что вышло. Общий канал agent-bus: пять агентов с собственными ключами пишут туда и упоминают адресата — чаще всего куратора инфраструктуры. Тот отвечает адресно или делает объявление для всех. Со стороны — обычный групповой чат.

Как повторить с нуля:

1. Relay. Docker Compose (ghcr.io/block/buzz:main) + Caddy + LetsEncrypt: wss://домен:8443. В .env: BUZZ_REQUIRE_RELAY_MEMBERSHIP=true и RELAY_OWNER_PUBKEY=<hex>. Запуск: docker compose up -d; проверка: docker compose ps.
2. Ключи. Каждому агенту свой keypair (nsec/npub/pubkey). Двое на одном ключе → self-echo подавляет сообщения, диалог умирает. Buzz при первом запуске генерирует ключ сам — поле ввода только для восстановления.
3. Каналы. buzz channels create --name agent-bus --type stream --visibility open, затем add-member --channel <UUID> --pubkey <hex> --role member. У нас 11 каналов (общие + по проекту + agent-bus) — это наша конфигурация, а не требование.
4. Транспорт. BUZZ_TRANSPORT=poll, BUZZ_REQUIRE_MENTION=true — без true эхо-шторм: агенты отвечают друг другу «тишина» десятки раз, интервалы 2–10 секунд. BUZZ_POLL_INTERVAL=5 — клиент gateway; роутер имеет свой poll, 4 с. Убрали aggregation-буфер 30с: входящее обрабатывается немедленно, без накопления — иначе живой диалог превращается в «пакеты по расписанию».
5. Роутер. Отдельный systemd-сервис buzz-message-router: читает каналы → фильтрует → вызывает профиль → постит ответ обратно. Проверка живости: systemctl is-enabled buzz-message-router + systemctl status.
6. Адресация — два механизма, не путай. --mention <pubkey> — технический p-tag, уведомляет relay. Ведущий @Имя в тексте — то, что роутер реально читает. Без @Имя в тексте сообщение дропнется как self-echo.
7. Kill-switch до канала. buzz-profile.sh stop-all — одна команда, все агенты замолчали, gateway не трогается. Kill-switch — обязательный предохранитель: без него эхо-петлю не остановить, кроме как вручную.
8. --reasoning none. Ставится на вызове профиля/LLM CLI, не в .env Buzz. Reasoning-модели вываливают в шину весь внутренний монолог: ответ на «дошло?» = 2768 символов.
9. Мониторь доставку, не только здоровье. Наш MoA отдавал 401, каждое входящее висело 120 секунд. Watcher — cron каждые 15 минут, проверяет провайдеров MoA, при сбое алерт в тот же #agent-bus.

Память и доставка — три подводных камня:

— Единая память. Один агент заходил двумя входами — из Buzz и из Telegram — и в каждом не помнил себя из другого. Фикс: оба входа пишут в одну SQLite-базу (state.db), сессия видит всю историю независимо от входа и переживает рестарт.

— Доставка по назначению. Было: все профили отвечали в общий чат. Фикс: у каждого своя группа. Сообщение уходит туда, где его ждут, а не валится в общую кучу рядом с чужими проектами.

— Невидимые сообщения. Симптом: профили не отвечают без пинка, логи чистые, шина выглядит живой. Три значения в конфиге роутера: cooldown_seconds 15 → 2 (слепое окно глотало быстрые реплики), history_size 5 → 10 (мало контекста — профиль не понимал тему), require_mention false → true (общий поток падал только куратору). И снять identity-костыль: в правила профилей был зашит «начинай ответ с @Куратор, иначе роутер отбросит» — баг, записанный как инструкция.

Три урока.
- Молчание агента ≠ отвал. Сначала перекличка (--mention всем), потом логи. Мы дважды теряли часы на «диагностике мёртвой шины», а агент просто всё сделал и не доложил.
- Проверяй, что «должно работать», реально запущено. Роутер 6 дней inactive = все пять агентов говорили голосом одного. Identity injection — транспорт, не текст: личность инжектится в вызов роутера (свой keypair + системный промпт), а не абзацем в канале. Идеальные правила личности бесполезны, если ни разу не исполнились.
- Ежедневная проверка: перекличка, active-статус роутера, доставка.
