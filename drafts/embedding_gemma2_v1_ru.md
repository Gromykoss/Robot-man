# Драфт RU v1 — EmbeddingGemma 2 на ноутбуке (dogfood Junior)
07.10 · факты: сообщение владельца + живая проверка Junior на машине; релиз 06.10, Apache 2.0
Anti-dub: OK (no overlap). Голос: спокойный инженерный отчёт, шаблон 1-7.

1. Хук (конфликт):
Google выпустила «нативно мультимодальный» эмбеддинг-модель — и впервые я могу запустить её целиком
на ноутбуке без видеокарты.

2. Что это:
EmbeddingGemma 2 (Apache 2.0): текст, код, изображения, аудио — одно 768-мерное пространство.
740M параметров: 270M text + 170M vision + 300M audio, и энкодеры модальностей отключаемые —
грузишь только то, что нужно.

3. Как работает (механика, цифры с живой машины):
- стек: torch 2.14.1+cpu + sentence-transformers, модель в HF-кэше 1.5 GB
- текст+код, энкодеры vision/audio отключены: загрузка 10.4 с, кодирование 114 мс/документ,
  запрос 80-111 мс, RAM ~1.5 GB
- ловушка из доков подтверждена: FP16 даёт NaN — только FP32/BF16; Matrёшка 768 → 512/256/128d;
  контекст 8K, 100+ языков
- сюрприз: кросс-языковая семантика из коробки — русские запросы находят английские документы
  (score 0.64-0.79) без перевода

4. Когда применять:
Когда нужны семантика и поиск без облака: индексация заметок, кадров, треков, документов.

5. Собственный опыт (наша машина):
HUAWEI BOD-WXX9, i5-1135G7 (4 ядра/8 потоков), 15.8 GB RAM, Intel Iris Xe shared — CUDA нет.
Узкое место — не память, а CPU: текст — 80-114 мс, кадры/клипы — секунды (прогон на тексте;
vision-энкодер отдельно). Для индексации — терпимо, для realtime — нет.

6. Честные минусы:
- CPU-скорость исключает realtime
- FP16-ловушка режет половину готовых пайплайнов
- «мультимодальность» = общий вектор, а не замена профильным моделям

7. Вывод (дуга):
Семантический поиск перестал быть серверной роскошью: полноценный мультимодальный индекс
влезает в 1.5 ГБ RAM ноутбука без дискретной графики. Локальный RAG — это теперь не проект,
а настройка.
