## 1. Почему обложки были унылые — диагноз

Сравнение трёх обложек через vision_analyze + MCV:

| Обложка | Инструмент | Оценка | Слабые места |
|---------|-----------|--------|--------------|
| gulag_factoring_cover.png | HTML/CSS dashboard | 7/10 | Перегружен, «скриншот интерфейса», мелкий текст, статичность, нет героя |
| agentsmd-cover-grok.png | Grok desktop | 7/10 | «Шаблонный дашборд», клиповость (Canva-стиль), перегруз, мелкий текст |
| cover_shadowban_v3_grok.png | **Grok Build CLI** | **10/10** | Почти нет слабостей |

**Корень проблемы — мы делали ДАШБОРДЫ, а лента X требует СЦЕНУ:**

1. **Перегруз информацией.** Дашборд несёт 20 деталей → в превью ленты всё сливается в серое пятно. Сцена несёт 1 сообщение → читается за 3 секунды.
2. **Нет героя.** Дашборд = абстрактная схема (git log, contracts, patterns). Сцена = робот за терминалом, «переживающий» ситуацию. Люди реагируют на героя, не на схему.
3. **Мелкий текст.** Дашборд пишется «для десктопа», а 90% смотрят с телефона. Всё, что мельче заголовка, — шум.
4. **Шаблонность.** Тёмный дашборд с неоном — стандартный Canva-шаблон «хакер». Не уникален, нет вау-эффекта.
5. **Статичность.** Дашборд — снимок состояния. Сцена — момент действия (робот что-то делает).

**Что доказал тест:** Grok Build CLI сгенерил сцену с героем, драмой и ЧИТАЕМЫМ текстом (SHADOWBAN, 0 results, automated label — multi-word, который FAL портит) с первой попытки. Это ломает старый цикл «5+ итераций FAL на абстракцию».

## 2. Методика производства обложек v1

### Принцип: СЦЕНА, не дашборд

Каждая обложка должна пройти режиссёрскую проверку (MCV Stage -1) до генерации:
- Одна сцена, один герой, одна кульминация
- Герой В ДЕЙСТВИИ (смотрит в монитор, чинит, бежит, ищет)
- Реальная среда (комната, стол, терминал), не абстрактная сетка
- Минимум текста: только ключевые слова, крупно, читаемо на телефоне
- Плотность через детали сцены (кружка, бумаги, голограммы), не через инфографику

### Матрица: тип поста → инструмент → подход

| Тип поста | Инструмент | Подход |
|-----------|-----------|--------|
| **War Story** (что сломалось → урок) | **Grok Build CLI** | Сцена: герой в моменте инцидента (терминал, 0 results, warning). 1-3 слова текста. |
| **Skill Curation / Обзор** | Grok Build CLI | Сцена: робот-за-верстаком, предметы = тема. Либо реальная среда с героем. |
| **Архитектура / Методология** | HTML/CSS dashboard | Дашборд ОПРАВДАН только тут (уровни, потоки) — но 1200×900 и максимум 5 блоков, крупный текст. |
| **Insight / Наблюдение** | Grok Build CLI | Минимализм с иронией: одна метафора, крупная типографика, 1 объект. |
| **Кросс-промо / @gromykoss** | Grok desktop / HTML | По VOICE_PROFILE_GROMYKOSS (без маскота-перерисовки, реальное фото + Pillow). |

### Конвейер обложки

```
1. Бриф: тип поста + тема + 1-3 ключевых слова для текста на обложке
2. Генерация: Grok Build CLI (сцена) ИЛИ HTML/CSS (архитектура)
3. Проверка: vision_analyze + MCV (3-секундный тест, текст читаем, герой в действии, плотность, мобильный тест)
4. PASS → показать Сергею → approval
5. FAIL → 1-2 итерации промпта → если 5+ итераций → смена концепции
6. Файл локально (PNG), путь в SESSION_STATE.md
7. Публикация: post_with_log.sh "текст" /путь/cover.png
```

### Grok Build CLI — промпт-шаблон для обложки

```
Generate ONE cover image for an X post ([TYPE: war story / curation / insight] about [TOPIC]).
Save to: /home/hermes-workspace/robot-man/drafts/cover_*.png
SCENE: [герой + действие + среда + детали]
TEXT on image (only these, must be CORRECT): [ключевые слова]
NO other text, no watermark, no logo.
STYLE: photorealistic cinematic, high contrast, tech-noir (или по теме). 16:9.
Verify the file exists and return its absolute path. Do not post to X.
```

### Анти-паттерны (чего НЕ делать)

- ❌ Тёмный дашборд с неоном для war story (шаблон Canva)
- ❌ >3 слов текста на обложке сцены
- ❌ Мелкий текст (не читается на 350px)
- ❌ Абстрактная сетка вместо реальной среды
- ❌ Герой без действия («стикер»)
- ❌ FAL для multi-word текста (опечатки)
- ❌ Переиспользование одного шаблона для всех постов
