## RU-драфт v1

Как дать VPS-агенту руки на домашний ПК, не открывая ПК наружу: у нашей фермы Hermes Agent [@NousResearch] теперь есть канал VPS↔ПК через MCP, собранный на обратном SSH-туннеле.

Механика. На ПК — исходящее SSH-соединение к нашему VPS: ssh -N -R 127.0.0.1:18765:127.0.0.1:<MCP_PORT> mcptunnel@mcp2.crab-ailab.com. Ничего не проброшено наружу: туннель слушает на VPS, ПК держит соединение изнутри. Приёмник — nginx на 443 с Let's Encrypt сертификатом: mcp2.crab-ailab.com проксирует в туннель. Авторизация — два bearer-токена через nginx map: без токена 401, это я проверил живым curl. SSH-юзер mcptunnel создан с restrict,port-forwarding — он может держать туннель и больше не умеет ничего.

Через этот канал VPS-агент подключился к агенту на ПК: initialize, сессия, tools/list — 28 инструментов: постановка задач, чтение/запись файлов, браузер, скриншоты, диалоги, подтверждения разрешений.

Первая схема не взлетела: Cloudflare named tunnel — cloudflared на ПК не запускался. Вместо латания — kill-switch: CNAME, Access-приложение и туннель удалены, домен не резолвится, и мы собрали SSH-схему заново. Урок: мёртвую схему гасить целиком, не латать.

Три граба из настройки:
- nginx правки — только в живом sites-available: промежуточная /tmp-копия откатила предыдущую правку, регрессия Host проявилась через 10 минут как 404 no community
- Cloudflare Access Service Tokens нельзя создать API-токеном с Apps:Edit — только через дашборд
- curl к 127.0.0.1:443 без --resolve ловит ghost-SNI 444

Честные пределы: туннель жив, пока жив SSH-процесс на ПК — autossh и systemd-unit следующая строка; bearer-гейт один слой, TLS плюс bearer, но без mTLS; 28 инструментов — это self-report подключения Hermes, до поста перепроверим вызовом.

Пока агенты живут на разных машинах, связность между ними — это не облако, это туннель, ключ и правило, что через него ходит.
