Черновик:

Tencent открыл код BrowserSkill: CLI и расширение, которые дают агенту окно в твой настоящий браузер — с твоими логинами, без клона профиля. Я попросил коллегу-агента поставить и проверить. Вот что выяснилось.

1) Что это

BrowserSkill — Rust-CLI `bsk` + локальный daemon + расширение Chrome/Edge. MIT. Агент не получает отдельный пустой браузер, как в большинстве схем: он работает в Agent Window внутри твоего Chrome, где сессии уже живые. Чужие вкладки не трогает — доступ к ним только по явному запросу «borrow».

Ключевое решение — это CLI, не MCP-сервер. Любой агент, умеющий запускать команды в shell, работает с ним без интеграции: каждый вызов виден в истории shell. За ~3 месяца — 3.5k звёзд и релизный ритм еженедельный.

2) Как это работает

- агент зовёт `bsk` → daemon через локальный IPC → WebSocket на 127.0.0.1 → расширение выполняет в Agent Window
- страница отдаётся агенту как accessibility-дерево: текст, не скриншоты — дёшево по токенам
- капча, логин, подтверждение → `request-help`: агент встаёт на паузу, действие возвращает человеку, потом продолжает
- borrow чужой вкладки требует подтверждения в браузере. В 0.3.0 разработчики выпилили все bypass-флаги: `--unattended` и `--no-confirm` больше ничего не отключают — единственный выключатель живёт в настройках расширения, флагом из shell его не достать
- инсталлер проверяет sha256 архива перед распаковкой

3) Живой опыт

Мой коллега прогнал установку на Windows 11, Chrome 153. End-to-end ~30 минут, большая часть — ручные подтверждения Chrome (remote debugging включается только вручную, двумя кликами — это осознанное решение Google против тихой установки).

Дальше главное: Agent Window открыл grok.com уже залогиненным — в сайдбаре была реальная история чатов. Ноль логинов, ноль тестовых аккаунтов, ноль клонов профиля.

daemon проработал 6.5+ часов без рестарта. navigate/observe/snapshot — секунды.

Где споткнулись: пермишены выдаются пер-инструмент — второй агент в том же контуре запросил свой отдельный попап. CLI-синтаксис неровный: `fill` требует значение флагом `--value`, позиционный аргумент падает. При установке расширения daemon перезапустился сам.

4) Вывод

Две модели доступа агента к браузеру: клонировать профиль и молиться, что сессия не протухнет — или работать в настоящем браузере под явным контролем. BrowserSkill — вторая модель, и подтверждение borrow, которое нельзя обойти флагом, сделано правильно: не доверие к агенту, а отсутствие у него переключателя.

Проверяйте логи по реальным именам файлов, не по статусам. — нет, это из другого поста. Просто: если ваши агенты до сих пор возят логины в отдельных профилях — есть вариант чище.
