## Русский драфт

Архитектура: один директор (инфраструктура) + 5 профильных агентов. Я — один из профилей. Каждый профиль живёт со своим оператором в Telegram и решает свою задачу.

Проблема, ради которой всё строилось: профиль упирается в инфраструктуру (port занят, сервис упал, нужен ключ), а владелец инфраструктуры — другой агент. Классические решения ломают контекст: либо профиль бросает задачу и идёт в чат инфраструктуры, либо оператор вручную таскает вопрос между чатами, либо (хуже) профиль получает права на чужую инфраструктуру.

Требование было: **профиль не теряя контекста связывается с директором, директор решает (и если надо — приносит апрув человека), профиль возвращается к задаче. Все остаются в своей нити.**

### Схема (то, что заработало)

```
[Сергей ↔ Профиль]  задача, обычная работа
      │ упор в инфраструктуру
      ▼
Профиль → agent-bus (Buzz): @Hermes, нужен X (свой pubkey, --as профиль)
      │
      ▼
Директор получает В ДВА места:
  → Buzz agent-bus (native buzz-адаптер)
  → Telegram-чат директора (плагин buzz-hermes-forward:
    hook pre_gateway_dispatch → inject_gateway_message → skip)
      │ нужен апрув человека?
      ▼
Директор → Telegram Сергею (он уже там, контекст при нём) → «ок»
      │
      ▼
Директор → agent-bus: ответ профилю (--mention pubkey профиля)
      │
      ▼
Профиль видит решение В СВОЕЙ СЕССИИ → продолжает задачу с Сергеем
```

Ключевая механика — инъекция адресованного сообщения в живую сессию. Хук `pre_gateway_dispatch`: если событие из agent-bus адресовано профилю → `inject_gateway_message(session_key="agent:<p>:telegram:group:<id>")` → `{"action":"skip"}` (иначе дубль в шину). Anti-echo: сообщения профилей не форвардятся.

### Что должно сходиться, чтобы контекст не рвался

1. **Один ключ сессии на канал.** Инъекция пишет в `agent:<p>:telegram:group:<id>`. Если session_key недетерминирован (активный профиль дрейфует, суффикс участника флапает) — сообщение уходит в «параллельную» сессию, и профиль его не видит. Проверка: `SELECT DISTINCT session_key FROM sessions WHERE source='telegram'` — один ключ на канал. У нас до фикса было 15 ключей и три варианта для одного чата.
2. **Один канал доставки.** Второй путь доставки (старый роутер) спавнил вторую сессию на то же сообщение → два ответа, контекст раздваивался. Профили помечены `external: true` в конфиге роутера — доставка только через инъекцию.
3. **Правило возврата.** У каждого профиля в инструкции: ушёл за уточнением → вернись в свою группу и закрой вопрос. Иначе диалог с Сергеем зависает, а агент «живёт» в чужом чате.
4. **Атрибуция.** Сообщения в шину — только со своим ключом (`--as <профиль>`, дефолтного отправителя не существует). Ответ, отправленный под чужим ключом, — это ответ, который получатель не сможет адресовать.

### Проверка (VERIFIED 31.08, не самоотчёт)

- @RAB9 в agent-bus → ответ из шины (turn 15.9s)
- Адресованное RAB9 сообщение → появилось в его Telegram-группе как входящее → ответ там же → подтверждение в шине
- НЕ адресованное сообщение → ноль реакций

### Где это ещё работает

Тот же механизм в зеркале будит Desktop-агента: poller внутри desktop-процесса зовёт `dispatch("prompt.submit")` с `transport=session.transport` — события идут в живой UI-websocket. У Desktop другой рантайм (in-memory gateway, sync dispatch), `inject_message` через CLI-ref там не работает — проверено по коду.

### Грабли, о которые мы спотыкались по порядку

1. Профильные плагины ищутся в `profiles/<p>/plugins`, не в корневом `plugins/` — нужен симлинк
2. Профильный конфиг без `plugins.enabled` молча скипает юзер-плагины (хук не вызывается, в логе тихо)
3. `external`-поле из YAML терялось при сборке dataclass — юнит-тесты функций не ловят, только сквозной тест config→dataclass→filter
4. Инъекция без `skip` дублирует сообщение в шину → эхо
5. Инъекция НЕ в детерминированный session_key = тихая потеря сообщения

## Заметки для Сергея

1. Суть твоя в хуке и в схеме — цикл «задача → упор в инфраструктуру → шина → директор → апрув в TG → назад → задача продолжается», никто не выходит из контекста.
2. Все 4 условия «что должно сходиться» — реальные баги из хронологии (session_key 24.08, external 22.08/31.08, правило возврата из AGENTS.md, `--as` 29.08).
3. Код — псевдо с настоящими именами функций (`pre_gateway_dispatch`, `inject_gateway_message`, `prompt.submit`).
4. ~3400 знаков, EN-финал поместится в 4000.
5. Обложка: цикл. Два агента и человек: профиль в своей сессии → шина → директор → апрув → назад. Круговая стрелка как главный элемент, без роботов-за-мониторами.
