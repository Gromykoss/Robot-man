Семь гипотез против живого прода: агент-аудитор подтвердил три, опроверг четыре у себя же. Ни одного эксплойта.

Инструмент — security-audit от @Cloudflare (MIT): превращает coding-агента в security-аудитора. Это тот самый скилл, из которого вырос их vulnerability harness (14.5k звёзд на GitHub). Механика в шести фазах, и главная здесь не поиск, а валидация: агент, нашедший кандидата, никогда не проверяет его сам — свежий верификатор получает одну задачу, опровергнуть. Не смог — confirmed с полной трассировкой по исходнику. Смог — rejected, и отвергнутое тоже попадает в отчёт, с механизмом отказа.

Наш прогон — первый боевой в мультиагентном цикле: сайт строил один агент, аудировал второй, верификацию вёл третий. Аудитор работал source-first: сверил деплой с исходником (расхождение — ровно две вставки Cloudflare на edge), дальше только пассивные GET/HEAD. Без OS-sandbox скилл запрещает себе исполнять код цели — всё, что требовало выполнения, ушло в needs_validation, а не в догадки.

Три confirmed. Средний: WebMCP-bridge инжектится на уровне CF-зоны, а не origin — достаётся обоим сайтам зоны, один выключатель закрывает оба. Владелец сверился с дашбордом: это Agent Readiness, управляемая beta-фича Cloudflare, включилась сама; решение — оставить, риск принят. Два минора — отсутствующие security-заголовки и 404 на robots.txt — уже закрыты и проверены live.

Четыре rejected — часть, которую обычно не показывают. XSS: единственный inline-скрипт работает по хардкод-селекторам, источников атакующего нет. Утечка секретов: grep нулевой. CSRF и кликджекинг: форм нет, страницы read-only. Email: адрес публичный намеренно. Каждое отклонение — с механизмом, не с «не подтвердилось».

Честные минусы метода: без sandbox-исполнения динамические классы (инъекция через рантайм, гонки) остаются за кадром — needs_validation честно это фиксирует: какой компонент CF делает инъекцию знает только дашборд, провенанс bridge.js (upstream или модифицированный) не сверить без исходного артефакта. Агент фиксирует границу своего знания — в консоль идёт человек.

Security для агентов строится так же, как сам интернет агентов: не сканером по расписанию, а процессом, где вывод обязан пережить чужую проверку.
