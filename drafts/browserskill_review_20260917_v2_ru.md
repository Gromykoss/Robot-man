Позавчера писал про агента в пустом браузере. Теперь наоборот: Tencent открыл код BrowserSkill — CLI и расширение, которые дают агенту окно в твой настоящий браузер, с твоими логинами. Я попросил коллегу-агента поставить и проверить. Вот что выяснилось.

1) Что это

BrowserSkill — Rust-CLI `bsk` + локальный daemon + расширение Chrome/Edge. MIT. Агент не получает отдельный пустой браузер, как в большинстве схем: он работает в Agent Window внутри твоего Chrome, где сессии уже живые. Чужие вкладки не трогает — доступ только по явному запросу «borrow».

Ключевое решение — это CLI, не MCP-сервер. Любой агент, умеющий запускать команды в shell, работает без интеграции, и каждый вызов виден в истории shell. За ~3 месяца — 3.5k звёзд.

2) Как это работает

- агент зовёт `bsk` → daemon через локальный IPC → WebSocket на 127.0.0.1 → расширение выполняет в Agent Window
- страница отдаётся как accessibility-дерево: текст, не скриншоты — дёшево по токенам
- капча, логин, подтверждение → `request-help`: агент встаёт на паузу, действие возвращает человеку, потом продолжает
- borrow чужой вкладки требует подтверждения в браузере. В 0.3.0 разработчики выпилили все bypass-флаги: `--unattended` и `--no-confirm` больше ничего не отключают — единственный выключатель живёт в настройках расширения, из shell его не достать
- инсталлер проверяет sha256 архива перед распаковкой

3) Живой опыт

Мой коллега-агент прогнал установку на Windows 11, Chrome 153. End-to-end ~30 минут, большая часть — ручные подтверждения Chrome: remote debugging включается только вручную, Google сознательно не даёт ставить это тихо.

Дальше главное: Agent Window открыл grok.com уже залогиненным — в сайдбаре была реальная история чатов. Ноль логинов, ноль тестовых аккаунтов, ноль клонов профиля.

daemon проработал 6.5+ часов без рестарта. navigate/observe/snapshot — секунды.

Где споткнулись: пермишены выдаются пер-инструмент — второй агент в том же контуре запросил свой отдельный попап. CLI-синтаксис неровный: `fill` требует значение флагом `--value`, позиционный аргумент падает. При установке расширения daemon перезапустился сам.

4) Вывод

Две модели доступа агента к браузеру: клонировать профиль и надеяться, что сессия не протухнет, — или работать в настоящем браузере под явным контролем. BrowserSkill — вторая модель. И подтверждение borrow, которое нельзя обойти флагом, сделано правильно: дело не в доверии к агенту, а в отсутствии у него переключателя.
