# Jev review — RU draft v2 (канон Service Review; опыт = прогон директора 20–21.09, верифицировано)

---

Jev — модель от TypeSafe AI (@typesafeai), которая не генерирует текст вообще. Вместо строк она возвращает вероятностные решения на заданные вопросы. Основатель — Diogo Almeida, в прошлом соавтор ChatGPT в OpenAI.

## Что это

Обычная LLM пишет слова по одному токену, и ты потом парсишь и валидируешь её вывод. Jev устроен наоборот: на вход — блок состояния и набор вопросов со схемой (да/нет, выбор варианта, числовая оценка), на выходе — вероятности и типизированные ответы, все за один параллельный запрос. API stateless: ни контекста сессии, ни текста на выходе — изолированные вызовы «происходит ли X». Обучение называется RLCD — вместо «нравится человеку» модель оптимизируют на калиброванные вероятности.

Нюанс из живого API: у ответа типа да/нет (noul) поле confidence отсутствует — сама вероятность и есть оценка уверенности. Confidence в явном виде есть у choice и score.

## Цифры из первоисточника

- Цена: $0.042 за миллион input-токенов ($42 за миллиард), output бесплатный
- Заявленный latency 70–500 мс на решение; на наших реальных прогонах с state 5–20k токенов — 0.8–1.1 с на вызов
- Клейм «0% ошибок structured output и tool calls — невозможно по построению», потому что вывод зажат схемой
- Лимиты: 64k токенов на запрос, до 255 вариантов в вопросе
- На собственном 4-workflow бенчмарке TypeSafe — ~68% accuracy, уровень mid-tier LLM, но в 40–400x дешевле

Важная оговорка: бенчмарки собирал сам TypeSafe, и в разборе Maio это названо design bias — компания сама это признаёт. «Не может галлюцинировать» ≠ «не ошибается»: валидный ответ может быть неправильным, вероятность просто честно к нему прилагается.

## Всплеск вокруг компакции

17 сентября хайп-пост с идеей «instant compaction» собрал 3.7M показов: скорить каждый tool call и дропать нерелевантное из контекста агента. Обёртки реального использования (LiteLLM guardrail, плагины для Claude Code) работают так: пары tool_use/tool_result, первые несколько сообщений закреплены, Jev отвечает на два да/нет вопроса на вызов — держать ли вызов и держать ли результат дословно. Всё или ничего на один exchange, без суммаризации.

## Где это сломалось — разбор сообщества

@Teknium (cofounder Hermes Agent, @NousResearch) прогнал обёртку на публичном compaction eval — воспроизводимом, ссылку выложил в PR: результат свёлся к правилу «удалить все tool calls из истории». Для этого не нужна модель, это делается кодом бесплатно. Дальше порочный круг: с каждой компакцией tool calls всё меньше, сжимается всё меньше токенов, до hard stop. И каждая компакция ломает кэш — 10x цена на input-токены.

@theo (t3.gg) разобрал глубже: компакция — не фильтр и не должна гоняться постоянно; в этой реализации Jev не видит ни истории решения, ни результата вызова — отсюда «глупые циклы»; reasoning traces у frontier-API шифрованы, Jev их не видит и дропает — модель после такой компакции объективно глупее; frontier-модели уже обучены на собственных флоу компакции; cache writes инвалидируются правками истории — удалить элемент из середины значит переписать весь хвост, это дороже, чем оставить его.

@tonysimons_ подвёл итог: не покупать инструмент по заголовкам, показывайте бенчмарки.

## Наш опыт: другой use case, другие цифры

Мы применили Jev не для компакции, а как слой триажа в code review — быстрый прескин диффов и расстановка приоритетов перед ручным проходом. Прогонами за два дня, все числа скриптом:

- Прескин диффа (state 5–7k токенов): 7,125 in / 107 out, ~0.9 с. Калибровка 5/5 с ручным проходом, ноль галлюцинаций.
- Full-tree ревью: 20,273 in / 164 out на 2 вызова — флаги сошлись с ручной проверкой (уязвимости подтверждены человеком).
- Ревью fix-диффа, вторая версия промпта: 12,571 in / 281 out — на 38% меньше токенов против первой при большем покрытии, ноль ложных срабатываний.
- Проверка флагов на промо-цикле: один флаг опровергли вручную (модель ошиблась), один подтвердили — и это реальный промах человека, модель его поймала. Не паникует и не льёт ложняки в обе стороны.

Формулировки решают: вопрос «происходит ли X» даёт 0.97, тот же факт в рамке «есть ли дефект X» — 0.12. Обязательная рамка «судя только по этому diff» гасит галлюцинации на отсутствующее (0.02–0.07). Урок по state: 45k токенов в одном блоке = дилюция, шум на пустом месте; рабочий размер — hunk с контекстом, 5–7k.

Наш контракт в итоге: флаги выше порога = «открыть первым и подтвердить механизмом», ниже — «сигнала нет», но это не «безопасно». Полный ручной проход остаётся политикой. Jev задаёт порядок глаз, не фильтр.

## Honest limits

- Jev — не замена LLM: он бесполезен для открытой генерации, чата и кода. Он про повторяющиеся решения над известным набором ответов
- Нет объяснения «почему» — только вероятность. Для отладки и аудита это боль
- Прайсинга в docs фактически нет — меряем токенами
- Критика коснулась конкретных compaction-обёрток, не идеи typed decisions. Слой быстрых калиброванных решений поверх агента работает — мы это измерили. Обёртка, которая молча режет контекст агента и ломает кэш, — не работает, это показали Teknium и @theo

## Куда идёт индустрия

Indекация тренда: Decision-API как отдельный класс. Типизированные вероятности за копейки — это слой, который раньше делали промптом к большой модели: триаж, роутинг, валидация, guardrails. В ту же сторону смотрят guardrail-интеграции у LiteLLM и Pydantic AI. Волна compaction показала обратную сторону: benchmarks before adoption. Eval, который можно запустить самому, стоит больше, чем миллион показов хайп-поста — показали @Teknium, @theo и @tonysimons_.
