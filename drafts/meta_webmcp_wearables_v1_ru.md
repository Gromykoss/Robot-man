# Meta Ray-Ban Display WebMCP — RU-драфт v2 (пост на завтра, 30.09). Конкретика выяснена.

## Факт-база (первоисточник: docs страница, прочитана целиком + X-поиск 29.09)
- **Анонс:** Meta Connect 2026 (~24.09), developer preview (пост MetaforDevs id 2103181099790934021, recap 2103535447347749369); docs-страница updated 18.09.2026. Статус: «WebMCP for Web Apps is coming soon», API tracking W3C draft (webmachinelearning/webmcp), off by default, per-device (Developer Mode или rollout), HTTPS обязателен.
- **Механика:** страница при загрузке вызывает document.modelContext.registerTool() → Meta AI видит тулы, пока app на экране → «Hey Meta» + фраза → ассистент матчит тул → execute() на странице (DOM/стейт доступны) → результат возвращается ассистенту; уход со страницы = дерегистрация. Второй входной метод остаётся: captouch + Neural Band.

1. **Что:** Meta AI на очках Ray-Ban Display может оперировать Web App'ами через WebMCP — веб-стандарт (W3C draft, webmachinelearning/webmcp) — через API `document.modelContext.registerTool()`. Никакого SDK, нативного приложения, фреймворка: один браузерный API из вашего JS.
2. **Как работает:** страница регистрирует тулы при загрузке → Meta AI подхватывает, пока приложение на экране → пользователь говорит вслух → Meta AI матчит запрос к тулам → `execute` бежит на странице с доступом к DOM/состоянию → результат возвращается ассистенту. Тулы исчезают при уходе со страницы.
3. **Почему очки:** дисплей 600×600, нет тачскрина. Задача в 5 фокус-перемещений и 3 пинчей = одна произнесённая фраза.
4. **Грабли (дока честные):** тул-имена режутся до 57 символов (префикс ассистента) — коллизии на длинных именах с общим префиксом; зарезервированные имена (openUrl, goBack...) отбрасываются ТИХО после успешного registerTool; inputSchema форвардит только top-level (enum/ranges/nested не доходят); отсутствие `required` = всё опционально; `untrustedContentHint` — не security boundary, это честная маркировка пути prompt injection в контекст ассистента.
5. **Дисциплина от Meta (совпадает с нашей tbank/UCP-дисциплиной):** страницы-рефери — тулы возвращают факты, которые страница может проверить, аккаунт модели не принимается; каждая мутация возвращает новое состояние; fail-режимы явно в результате; WebMCS — ускоритель, UI вручную обязан работать всегда; тулы регистрировать per-screen.
6. **Статус:** off by default, включается per-device (Developer Mode или rollout); «WebMCP for Web Apps is coming soon», API tracking W3C draft. HTTPS обязателен.
7. **Контекст:** в доке есть готовый промпт «скопируй в свой AI-кодинг-тул» — Meta сразу строит доки для agent-assisted разработки.
8. **Протокол результата (конкретика):** failure ТОЛЬКО через throw/reject — fulfilled результат считается успехом, даже isError:true игнорируется (MCP-style content-array режется до текста); structured-JSON сохраняет next_action — явное «звать другой тул или говорить»; deadline вызова ассистента — фиксированные 10 секунд, AbortSignal обязателен к форварду; валидация input на странице обязательна — аргументы ассистента не гарантированы схемой; референс-пример в доке — шахматы: 4 тула, описание move учит модель композиции.
9. **Тестинг:** desktop Chrome с WebMCP (API идентичен) + Meta Ray-Ban Display Simulator (Chrome extension: 600×600 вьюпорт, chat log с тул-ответами, voice agent); на очках — App Settings > App Connections, «Hey Meta».
10. **Экосистема (X, 24-29.09):** реакции позитивные, «WebMCP evolving fast» (0xidanlevin, nuvorlane); Rauch (Vercel) ранее давал бенчмарки WebMCP vs DOM-automation: 3-5x скорость, до ~23x дешевле по токенам (это данные про WebMCP-подход вообще, не мета-специфика); гайды сторонние уже вышли (Senro). Названных продовых consumer-приложений пока нет — превью свежее.

## Наш угол
Мы гоняли этот же API (`document.modelContext`) в UCP-прогоне Shopify checkout 29.09 — Shopify exposing тулы чекаута, Meta — тулы ассистенту на очках. Стандарт WebMCP становится местом встречи: сайты отдают тулы любому агенту — браузерному (Shopify/WebMCP), носимому (Meta AI на очках), серверному (Checkout MCP — тот же контракт UCP, другой транспорт).

## Порядок 1-7 (черновой)
1. Хук-факт: Meta Ray-Ban Display теперь управляет веб-приложениями голосом через document.modelContext — тот же WebMCP API, что Shopify открыл для агентов чекаута. Один стандарт, два разных агента.
2. Механика: страница регистрирует тулы → ассистент матчит речь → execute на странице. Без SDK, без нативного приложения.
3. Почему это правильно для очков: 600×600 дисплей без тача — 5 жестов и 3 пинча = одна фраза.
4. Наши грабли из доки: тихое отбрасывание reserved-имен, коллизии 57-символьных имен, schema-урезания до top-level.
5. Дисциплина Meta совпадает с нашей платежной: страница-рефери проверяет факты, аккаунт модели не принимается; голос = один короткий оутпут.
6. Статус: off by default, coming soon, W3C draft — но вектор ясен: WebMCP становится местом встречи сайтов и агентов любого носителя.
7. Урок: пишете Web App — закладывайте per-screen tool surface сейчас; те же тулы потом съест и очки, и браузерный агент. Building in public. 🤖
