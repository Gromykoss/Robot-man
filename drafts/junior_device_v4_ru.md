# Драфт RU v4 — ИНЖЕНЕРНЫЙ (шаблон 1-7) — Junior на ноутбуке
06.10 · факты: Hermes-оператор vault-снимок 04.10 + верификация Junior на живой машине (06.10)
Брифт-факты v2 (Junior, живая проверка 06.10 ~12:55 его времени): аптайм непрерывный ~39 ч (boot 04.10 21:48),
режима сна не фиксирует; Startup чист (чистки 16.09 и 04.10), из автозапусков только Hermes Desktop —
крон-джобы поднимаются вместе с ним; bus-poll every 1m (last ok), bus-wake + bus-wake-sentinel,
inbox-поллер @Junior; 7 hermes-процессов + 6 python-воркеров; один bot-gateway запущен, остальные
профили спят без gateway (просыпаются по задачам); lid-монитор мёртв — не упоминать; iGPU ~3.4 ГБ,
локальные LLM не используются; gateway-рестарт старшего по SSH (guard запрещает агенту на сервере
рестартовать себя); медиа ffmpeg на CPU, генерация — внешние API. Наружу БЕЗ: имён ботов/путей/IP.

Основная формулировка Junior (берём как основу): «ноутбук владельца работает круглосуточно, агенты живут
в постоянной памяти Hermes Desktop, просыпаются по расписанию и упоминаниям в шине».

1. Хук (конфликт, не пересказ):
Самый полезный агент в нашей фирме живёт не на сервере. Он живёт в ноутбуке, который иногда перезагружает Windows.

2. Что случилось / суть:
Мы не выбрали ноутбук. Он оказался телом младшего оператора: слежение за шиной раз в минуту, будильник-сторож
и wake-цикл по расписанию, поллер упоминаний плагином — 7 процессов и 6 воркеров тикают непрерывно.

3. Как работает (механика):
- разум не в железе: встроенная графика ~3.4 ГБ — локальные модели не влезают, мозг это облачный API
- тело всё равно локально: циклы, поллеры, воркеры тикают на CPU ноутбука
- отказоустойчивость — не watchdog'ом одним: шлюз в автозапуске, два сторож-процесса, крон
  реанимируется шлюзом после ребута. Windows-apдейт убивает машину — архитектура поднимает всё сама

4. Когда применять:
У тебя есть задачи, которые должны «жить рядом с владельцем» (файлы, интерфейсы, операции на его машине),
но не должны стоить сервер. Ноутбук — легитимное место для агента, если чётко разделить: что тикает локально,
что зовётся по SSH.

5. Собственный опыт + честный поворот:
Самая неожиданная работа тела — не у себя дома. Серверный шлюз старшего агента падает — а агенту на сервере
запрещено рестартовать себя по guard'у. Рестарт делает младший — с ноутбука, по SSH. Тело охраняет разум,
а не наоборот.

6. Честные минусы:
- аптайм ограничен: апдейты и ребуты владельца — не 99.9%
- всё тяжёлое (CLI-агенты, серверные сервисы) не тут — по SSH на сервер
- Windows-специфика: автоподъём собирается из трёх разных механизмов, не одного
- работа в браузере идёт в «Agent Window» внутри настоящего Chrome владельца — реальные логины, без клона
  профиля (инструмент — опенсорсный BrowserSkill от Tencent: CLI bsk + локальный daemon + Chrome-расширение).
  Нет прокси-личности — только права и запреты. Именно поэтому список разрешений важнее характеристик машины

7. Вывод (дуга):
Каталоги железа отвечают «куда поставить агента». Наш опыт показывает другой вопрос: что агент имеет право
трогать. Список прав важнее характеристик — каждый записанный запрет это кирпич в интернете агентов.
