# Jev review — RU draft v1 (канон Service Review, без хуков)

---

Jev — модель от TypeSafe AI (@typesafeai), которая не генерирует текст вообще. Вместо строк она возвращает типизированные решения с калиброванной вероятностью. Основатель — Diogo Almeida, в прошлом соавтор ChatGPT в OpenAI.

## Что это

Обычная LLM пишет слова по одному токену, и ты потом парсишь и валидируешь её вывод. Jev устроен наоборот: на вход — блок состояния и набор вопросов со схемой (выбор из вариантов, числовая оценка, да/нет), на выходе — готовые типизированные ответы, все за один параллельный запрос. Обучение называется RLCD — вместо «нравится человеку» модель оптимизируют на калиброванные вероятности решений.

## Цифры из первоисточника

- Цена: $0.042 за миллион input-токенов ($42 за миллиард), output бесплатный
- Latency: 70–500 мс на решение (демо TypeSafe: 0.114 с за $0.000081)
- Заявленный клейм: «0% ошибок structured output и tool calls — невозможно по построению», потому что вывод зажат схемой
- Лимиты: 64k токенов на запрос, до 255 вариантов в одном вопросе, 250K tok/s
- На собственном 4-workflow бенчмарке TypeSafe — ~68% accuracy, уровень mid-tier LLM, но в 40–400x дешевле

Важная оговорка: бенчмарки собирал сам TypeSafe, и в посте Maio это названо design bias — компания сама это признаёт. «Не может галлюцинировать» ≠ «не ошибается»: валидный ответ может быть неправильным, уверенность просто честно к нему прилагается.

## Всплеск вокруг компакции

17 сентября хайп-пост с идеей «instant compaction» собрал 3.7M показов: скорить каждый tool call и дропать нерелевантное из контекста агента. Обёртки реального использования (LiteLLM guardrail, плагины для Claude Code) работают так: пары tool_use/tool_result, первые несколько сообщений закреплены, Jev отвечает на два yes/no вопроса на вызов — держать ли вызов и держать ли результат дословно. Всё или ничего на один exchange, без суммаризации.

## Где это сломалось — разбор сообщества

@Teknium (cofounder Hermes Agent, @NousResearch) прогнал обёртку на публичном compaction eval — воспроизводимом, ссылку выложил в PR: результат свёлся к правилу «удалить все tool calls из истории». Для этого не нужна модель, это делается кодом бесплатно. Дальше порочный круг: с каждой компакцией tool calls всё меньше, сжимается всё меньше токенов, до hard stop. И каждая компакция ломает кэш — 10x цена на input-токены.

@theo (t3.gg) разобрал глубже, пять пунктов: компакция — не фильтр и не должна гоняться постоянно; в этой реализации Jev не видит ни истории решения, ни результата вызова — отсюда «глупые циклы»; reasoning traces у frontier-API шифрованы, Jev их не видит и дропает — модель после такой компакции объективно глупее; frontier-модели уже обучены на собственных флоу компакции; cache writes инвалидируются правками истории — удалить элемент из середины значит переписать весь хвост, это дороже, чем оставить его.

@tonysimons_ подвёл итог: не покупать инструмент по заголовкам, показывайте бенчмарки.

## Honest limits

- Jev — не замена LLM: он бесполезен для открытой генерации, чата и кода. Он про повторяющиеся решения над известным набором ответов
- Нет объяснения «почему» — только число с вероятностью. Для отладки и аудита это боль
- Критика коснулась конкретных compaction-обёрток, не идеи typed decisions. Дешёвый слой быстрых калиброванных решений поверх агента — рабочая мысль; обёртка, которая молча режет контекст и ломает кэш, — нет

Тренд, в который это вписывается: индустрия начинает разделять «медленное рассуждение» и «быстрое решение» как два разных продукта. Пока compaction-волна показала обратную сторону — benchmarks before adoption. Показали Teknium, @theo и @tonysimons_: eval, который можно запустить самому, стоит больше, чем миллион показов хайп-поста.
