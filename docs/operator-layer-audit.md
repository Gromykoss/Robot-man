## 4. Что уже есть в коде (фундамент, НЕ переписывать)

- **`loop_guard.py`** — `Guard` (таймаут, бюджет, max_iterations, идемпотентность, эскалация). Единственный детерминированный guard-слой. Но только для циклов, к публикации не привязан.
- **`scripts/self_heal.py`** — классификация ошибок (429, rate-limit, permanent→human-gate). Аналитика, не enforcement.
- **`scripts/deploy.sh`** — git-check → py_compile → smoke (детерминированная проверка при деплое).
- **`x_tracker_fetch.py`** — чистый fetch, фильтрация по автору, dry-run флаг.

**Чего нет нигде в коде:** approval-токена, счётчика вритов/день, проверки аккаунта, факт-чека, анти-бан матрицы. Всё это живёт только в AGENTS.md как текст.

## 5. Вывод

Как и в Alikhan до переноса — **правила публикации (P0-P1) вообще не enforced**. `post_with_log.sh` — это «дырявая труба»: любой вызов мгновенно публикует пост безусловно, без approval, без счётчика лимитов, без проверки аккаунта.

Это ровно тот слой, который надо закрыть операторами:
- `operator_approval.py` — Human Gate (approval-токен обязателен для production-поста)
- `operator_limits.py` — счётчик вритов/день (пишется в `data/`, проверяется до поста)
- `operator_account.py` — валидация аккаунта (не допустить пост не на тот аккаунт)
- `operator_factcheck.py` — факт-чек (цифры/даты/имена — сверка с брифингом)

Точка безусловного вызова — **внутри `post_with_log.sh`** (или его python-обёртки), а не в промпте.
